# Лендинг Chanly

Публичный сайт Chanly на Vue 3. На маршруте `/` доступны девять блоков лендинга V3.4, якоря и возврат наверх. Демонстрация кабинета и оценка дохода работают на компьютере и телефоне. В FAQ можно раскрывать ответы, а в контактной форме — проверять заполнение полей.

## Запуск

Используйте Node.js 24.15.0 (см. [.nvmrc](.nvmrc)). Из корня репозитория выполните:

```sh
npm ci
npm run dev
```

Откройте локальный адрес, который напечатает Vite.

## Проверки и сборка

| Команда | Результат |
| --- | --- |
| `npm run lint` | ESLint проверяет JavaScript и Vue SFC. |
| `npm test` | Vitest один раз запускает тесты компонентов. |
| `npm run build` | Vite создаёт production-сборку в `dist/`. |
| `npm run preview` | Запускает локальный просмотр последней сборки. |

Для визуальной приёмки запустите `npm run build`, затем `npm run preview`. В чистом профиле проверьте страницу на ширине 1440 px и на экране 390 × 844. Перед полноразмерным снимком прокрутите все девять секций, дождитесь появления содержимого и загрузки изображений. Для проверки якорей откройте `/#faq` напрямую, перейдите в другой раздел и нажмите «Назад». Заголовок вопросов должен получить фокус и остаться видимым под шапкой.

Каждый pull request проходит чистую установку, ESLint, Vitest, тесты выпуска на Linux и сборку. CI проверяет ссылки на JS, CSS и иконку в `dist/index.html`. [Workflow](.github/workflows/ci.yml)

## Работа с компонентами

[BaseButton](src/components/BaseButton.vue) по умолчанию имеет тип `button`; для отправки формы передайте `type="submit"`. Свойства `disabled` и `loading` блокируют действие. [BaseField](src/components/BaseField.vue) принимает `label`, `v-model` и текст `error`. Состояние формы остаётся у вызывающего компонента.

Общие цвета, размеры и параметры движения находятся в [теме](src/assets/styles/_tokens.scss). Состав секций, ссылки на оба макета Figma и критерии приёмки приведены в [требованиях к лендингу](docs/landing-requirements.md).

## Страница и навигация

[HomeView](src/views/HomeView.vue) задаёт порядок первых восьми блоков. Шапка, девятый блок (подвал) и стрелка находятся в [SiteLayout](src/layout/SiteLayout.vue). Для нового якоря укажите уникальный ID на секции и тот же фрагмент в ссылке. Смещение под закреплённую шапку и переходы по истории обрабатывает [useLandingNavigation](src/composables/useLandingNavigation.js).

Чтобы проверить движение, откройте главную, прокрутите до преимуществ, перейдите к вопросам и вернитесь назад. Уже показанные секции остаются видимыми до перезагрузки. Включите в браузере `prefers-reduced-motion: reduce`: лента и крупный логотип останавливаются, якоря работают сразу. На 390 px ссылки шапки остаются во втором ряду.

Кнопки подключения открывают `/auth/login` полной навигацией. При переходе с защищённой страницы они сохраняют внутренний адрес кабинета в `next`. Адрес входа задаёт `VITE_AUTH_URL` во время сборки. Сообщение о переходе можно отключить через `VITE_LOG_LEVEL=silent`.

## Демонстрация и оценка дохода

Четыре экрана кабинета переключаются каждые 20 секунд с момента появления секции. Выбор шага вручную запускает отсчёт заново. При уменьшенном движении шаги переключает посетитель.

Калькулятор использует средние просмотры одного поста и число размещений за месяц. Для изменения тематики отредактируйте её подпись или ставку в [справочнике](src/data/incomeTopics.js). Поле `rate` хранит целые копейки за 1 000 просмотров. Ставки черновые и сохраняются между посещениями. Сумма за месяц округляется до копейки после учёта всех размещений. Контрольные примеры и переключение экранов проверяет `npm run test`.

## Вопросы и обратная связь

В FAQ можно раскрыть один из пяти ответов или свернуть текущий. Форма «На связи» проверяет имя, электронную почту, вопрос и согласие. Пока способ доставки выбирается, кнопка «Проверить поля» выполняет локальную проверку. Введённые данные остаются в памяти компонента.

Для подключения доставки потребуется выбрать получателя и согласовать, каким ответом сервер подтверждает доставку. Компонент ContactSection принимает асинхронную функцию `deliver({ name, email, question, consent })`. Результат `{ delivered: true }` подтверждает доставку и очищает форму. При отказе или исключении форма сохраняет введённое для повторной попытки. Состояния ожидания, сбоя и успеха можно проверить командой `npm run test -- tests/components/ContactSection.spec.js` с тестовым обработчиком.

Уведомления закрываются вручную или через 10 секунд после появления каждого. Баннер сохраняет только признак закрытия в localStorage под ключом `chanly:cookie-notice-dismissed`. Чтобы повторить первый визит, удалите этот ключ в инструментах браузера.

## Сборка и выпуск

| Событие | Результат |
| --- | --- |
| Push в `dev` | Проверки, сборка со входом через `https://dev.chanly.ru/auth/login` и автоматический выпуск на `dev.chanly.ru`. |
| Push в `master` | Проверки и сохранение production-архива для `chanly.ru`. Кнопки подключения ведут на `https://chanly.ru/auth/login`. |
| Pull request | Проверки и сборка с относительным адресом входа для предпросмотра. |

Архив `landing.tar.gz` доступен в артефактах соответствующего запуска 14 дней. Ветка `master` собирает production-артефакт без автоматической публикации.

### Стенд dev.chanly.ru

За внешним Basic Auth гость открывает лендинг по `/`. Для вошедшего Caddy проверяет сессию через API и отдаёт приложение. Домашний экран выбирает фронтенд. У лендинга свой каталог `/landing-assets/`.

1. Для повторного выпуска в GitHub Actions откройте «Проверка лендинга», выберите **Run workflow**, ветку `dev` и операцию `release`. Задание `check` проверяет сборку и сохраняет архив. Задание `deploy` сверяет SHA-256 и передаёт этот архив на стенд. В журнале видны Git SHA, ID запуска и контрольная сумма. [Запуски](https://github.com/leha-creator/chanly-landing/actions/workflows/ci.yml)
2. На сервере `readlink /opt/maxim-dev/frontend/landing/current` показывает активный каталог в формате `releases/<git-sha>-<sha256>`. Файл `landing/state.json` рядом с этой ссылкой хранит номер запуска, текущую и предыдущую версии. Хешированные ресурсы остаются в `landing/shared/landing-assets/` для уже открытых страниц.
3. Откройте корень гостем, перейдите из лендинга на вход. В новой сессии автора проверьте переход на `/blg/placements`, рекламодателя — на `/adv/catalog`. При прямом входе на защищённую ссылку проверьте возврат по `next` после авторизации.
4. Для возврата выберите в том же workflow операцию `rollback`. Она переключает на предыдущую версию под общей блокировкой и проверяет её по HTTPS. Повторный **новый запуск** операции меняет версии местами. При откате первого выпуска гостю снова доступна исходная SPA. При сбое проверки после переключения обработчик возвращает прежнюю ссылку и завершает запуск ошибкой.

### Доступ для выпуска

Перед первым push в `dev` настройте GitHub Environment `dev`: разрешите ветку `dev` и задайте в этом окружении действующие SSH-секреты стенда. Раньше стенд использовал окружение `production`; GitHub не переносит его секреты при смене имени в workflow. Секрет `DEPLOY_SSH_KEY` содержит отдельный ключ лендинга, `DEPLOY_KNOWN_HOSTS` — проверенный ключ хоста. Для публичного ключа пользователя `deploy` в `authorized_keys` заданы опции `restrict,command="/opt/maxim-dev/landing-release.py"`. При изменении обработчика установите проверенную версию `deploy/release.py` на этот путь с режимом 755 до использования нового протокола. Для локальной проверки обработчика на Linux выполните `python3 -m unittest discover -s deploy/tests` с Python 3.11 или новее.

HTTPS-проверка использует серверный `/opt/maxim-dev/basic-auth.curl` и файл `/opt/maxim-dev/landing-session.curl` с действующей сессией тестового кабинета. Оба файла доступны только пользователю `deploy` (0600). Когда сессия истекает, войдите в тестовый кабинет на dev обычным способом и обновите строку `cookie = "session=<значение>"` во втором файле. Проверка `/api/v1/me` остановит выпуск до переключения, если сессия уже истекла.

Для полного отката трёх репозиториев сначала верните предыдущие гостевые переходы фронтенда, затем конфигурацию Caddy. Переключатель фронтенда — переменная `SHARED_LANDING` репозитория приложения, которую учитывает сборка для выпуска ветки `dev`. Инструкции владельцев — [фронтенд](https://github.com/leha-creator/chanly-frontend/blob/dev/deploy/README.md) и [бэкенд](https://github.com/leha-creator/chanly/blob/dev/deploy/app/DEV.md).
